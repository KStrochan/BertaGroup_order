# Berta HoReCa — сайт онлайн-замовлень

Готовий B2B-каталог без реєстрації клієнтів. Замовлення надсилаються одним Telegram-ботом у групу **Berta Order**. Сайт показує повідомлення **«Замовлення відправлено»** тільки після успішної відповіді Telegram API.

## Що вже реалізовано

- 967 товарів з наданих Excel-прайсів:
  - Food — 513;
  - NONFood — 454.
- Початкові ціни з Excel, без застосування знижок.
- Пошук і фільтрація за категоріями.
- Кошик зі зміною кількості та автоматичним розрахунком суми.
- Збереження кошика у браузері клієнта.
- Оформлення без реєстрації:
  - ФОП / компанія;
  - контактна особа;
  - телефон;
  - місто;
  - вулиця;
  - номер будинку;
  - приміщення, дата доставки та коментар — необов’язкові.
- Доставка позначена як доступна по Львівській області.
- Сервер повторно перевіряє ціни за власним каталогом — клієнт не може підмінити суму в браузері.
- Захист від простого спаму та обмеження частоти запитів.
- Якщо замовлення довге, бот надсилає його кількома послідовними повідомленнями.
- Клієнти та історія їхніх замовлень зберігаються в безкоштовній базі Upstash Redis (див. розділ «База даних»). Кожне замовлення також надходить у Telegram-групу.

## Запуск на комп’ютері

Потрібен **Node.js 20 або новіший**.

### 1. Створіть файл `.env`

Скопіюйте `.env.example` у `.env`:

```bash
cp .env.example .env
```

У Windows можна просто створити копію файлу та перейменувати її на `.env`.

### 2. Додайте актуальний токен

Відкрийте `.env` і вставте новий токен бота:

```env
TELEGRAM_BOT_TOKEN=ВАШ_АКТУАЛЬНИЙ_ТОКЕН
TELEGRAM_CHAT_ID=-1004299599812
PORT=3000
```

Токен не можна публікувати або завантажувати в GitHub. Файл `.env` уже доданий до `.gitignore`.

### 3. Запустіть сайт

```bash
npm start
```

Відкрийте:

```text
http://localhost:3000
```

## Перевірка налаштування

У браузері відкрийте:

```text
http://localhost:3000/api/health
```

Очікувана відповідь після додавання токена:

```json
{
  "ok": true,
  "telegramConfigured": true,
  "productCount": 967
}
```

Після цього додайте тестовий товар у кошик і оформіть замовлення. Повідомлення **«Замовлення відправлено»** з’явиться тільки після того, як Telegram підтвердить надсилання в групу.

## База даних (Upstash Redis)

Клієнти й історія замовлень зберігаються в безкоштовній базі [Upstash Redis](https://upstash.com). Якщо змінні `UPSTASH_REDIS_REST_URL` і `UPSTASH_REDIS_REST_TOKEN` не задані, сервер працює з локальними JSON-файлами в папці `data/` — це лише для розробки на комп'ютері (на Render диск тимчасовий, і такі дані зникають при перезапуску).

### Підключення

1. В Upstash створіть базу Redis із безкоштовним планом.
2. Відкрийте базу → **Details → REST API** і скопіюйте `UPSTASH_REDIS_REST_URL` та `UPSTASH_REDIS_REST_TOKEN`.
3. Локально додайте обидва значення у `.env` (цей файл у `.gitignore`). На Render додайте ті самі змінні в **Environment**.
4. Запустіть сервер і відкрийте `/api/health` — там має бути `"storage": "upstash-redis"`.

Ключі ніколи не потрапляють у Git — навіть у `.env.example` (там лише заглушки). Якщо ключ опинився в репозиторії, вважайте його скомпрометованим: скиньте токен в Upstash і замініть значення на Render.

При старті сервер перевіряє з'єднання з базою. Якщо Redis налаштований, але недоступний, сервер не запускається й пише причину в лог: краще так, ніж працювати з порожньою базою, коли клієнти не зможуть увійти.

### Як зберігаються дані

Кожен запис — окремий ключ, тому одночасні запити не затирають один одного (раніше всі клієнти лежали одним великим JSON, а замовлення — іншим).

| Ключ | Що зберігає |
|---|---|
| `berta:user:<id>` | клієнт (JSON) |
| `berta:userphone:<телефон>` | id клієнта; гарантує унікальність телефону |
| `berta:users:all` | усі id клієнтів за часом реєстрації |
| `berta:order:<id>` | замовлення (JSON) |
| `berta:orders:all` | усі id замовлень за часом |
| `berta:orders:user:<id клієнта>` | id замовлень одного клієнта |
| `berta:schema` | `2` після переносу зі старого формату |

У кабінеті клієнта показуються його 500 останніх замовлень. Якщо база тимчасово недоступна в момент замовлення, воно все одно йде в Telegram, а сервер лише пише помилку в лог.

### Перенос зі старого формату

Старі ключі `berta_users` і `berta_orders` (по одному JSON-масиву на всіх) автоматично переносяться в нову структуру при першому запуску цієї версії. Самі старі ключі не видаляються — це резервна копія. Коли переконаєтесь, що все працює, їх можна видалити в Upstash → Data Browser. Щоб виконати перенос повторно, видаліть ключ `berta:schema` і перезапустіть сервер.

## Важливо перед публікацією

- Використовуйте тільки новий токен, який не надсилали у відкритих повідомленнях.
- На хостингу додайте `TELEGRAM_BOT_TOKEN` як секретну змінну середовища.
- `TELEGRAM_CHAT_ID` уже встановлено: `-1004299599812`.
- Бот повинен залишатися учасником групи **Berta Order** і мати право надсилати повідомлення.
